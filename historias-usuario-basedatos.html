B

Integridad referencial y consistencia

Reglas que hoy solo vive en el código de la API, y que la base de datos debería poder hacer cumplir por su cuenta.

US-DB-004candidata

Enlazar assigned_to con users.id

Como responsable de datos, quiero que tickets.assigned_to sea una llave foránea hacia users.id, para que la base rechace asignar un ticket a un usuario que no existe.

Hoy es un INT suelto, sin REFERENCES; nada impide guardar un id inventado.

Tocatickets.assigned_to
US-DB-005candidata

Restringir tickets.status a valores permitidos

Como responsable de datos, quiero que la base solo acepte OPEN, IN_PROGRESS o DONE en status, para que la validación no dependa únicamente del código de la API.

Hoy status es VARCHAR(50) libre; la lista de valores permitidos vive solo en tickets.py.

Tocatickets.status
US-DB-006candidata

Restringir users.role a valores válidos

Como responsable de datos, quiero que role solo acepte los roles definidos, para evitar variantes como "Admin" o "administrador" que rompan el enrutamiento por rol en el frontend.

Hoy conviven "admin" y "user" como texto libre, sin ninguna validación en la base.

Tocausers.role
US-DB-007candidata

Evitar nombres o correos de usuario duplicados

Como responsable de datos, quiero una restricción única sobre email, para que POST /login nunca tenga que elegir arbitrariamente entre dos personas con el mismo nombre.

POST /login hace WHERE name = %s OR email = %s LIMIT 1 — con nombres repetidos, el resultado depende del orden interno de la tabla.

Tocausers.email
US-DB-008candidata

Sincronizar schema.sql con la estructura real de la base

Como equipo de desarrollo, quiero que el script de esquema refleje exactamente las columnas y tipos que existen en la base de datos, para que alguien nuevo pueda levantar el entorno desde schema.sql sin sorpresas.

schema.sql declara tickets.created_by como INT, pero la base real tiene VARCHAR(50) — así es como la usa la aplicación hoy.

Tocadatabase/schema.sql

US-DB-010candidata

Usar una cuenta MySQL de mínimo privilegio para la app

Como responsable de seguridad, quiero que la API se conecte con un usuario limitado a la base soporte_ai (sin privilegios de administrador), para reducir el impacto si esas credenciales se filtran.
