Lectura rápida

De las 57 historias, el patrón más claro es que el hueco casi nunca es de una sola capa — es la misma idea vista desde tres ángulos (ej. "seguridad del login" = frontend sin persistencia + backend sin validar password + base de datos con la columna lista pero sin usar). Si hubiera que priorizar un solo esfuerzo, cerrar el Flujo 1 (login real) resolvería 3 de frontend + 2 de backend + 3 de base de datos de un tiro, porque las piezas ya están construidas esperándose entre sí.
